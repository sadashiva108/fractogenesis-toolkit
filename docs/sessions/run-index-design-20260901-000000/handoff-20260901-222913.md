## 3. `time-machine/` — see the design record

**`docs/architecture/time-machine-run-index.md`** is authoritative: the

What follows is the summary only.

### Approach, deliberately not started

**Chosen:** one run per invocation, lineages named for the subcommand, with the
`tmutil latestbackup` stamp in the manifest row's `Note` where it resolves — so
grouping stays recoverable without a second relayout.

**Why it was not started.** It was scoped as six artifact kinds from one script.
It is **nine, across two coupled producers**:

| Producer | Writes |
|---|---|
| `run-time-machine.sh` | `status`, `logs`, `completion-check`, `compare`, `verifychecksums`, `diagnose` |
| `record-time-machine-evidence.sh` | `pre-image-time-machine-status-*/`, `diskutil-verifyvolume-applebackups-*.txt`, `final-time-machine-checklist-*.md` |

`record-time-machine-evidence.sh final` reads **four** of the other script's
artifacts back by `-maxdepth 1` glob (`latest_matching_file` at line 441, used at
508/511/517; the `find … -name 'pre-image-time-machine-status-*'` at 523). All
four break the moment files move under `runs/`, so both producers and every
read-back must change in one edit. `reimage-checklist.sh` and
`record-reimaged-system.sh` also read the category.

**Three things to know before touching it:**

- `run-time-machine.sh` calls `artifact_path` inside a command substitution
  (`out="$(artifact_path status txt)"`). `artifact_run_begin` sets shell
  variables and a subshell discards them, so the **call sites change shape**, not
  just the helper.
- The dispatch `case` is the last statement in the file and exactly one command
  runs per invocation, so a single EXIT trap can finalize or abort every
  command's run without touching their early-return paths.
- Exit status **3** (verify-latest reporting checksum mismatches) should
  **finalize, not abort**. A run that reported findings is a completed run and
  the findings are the evidence; discarding it throws away the only record of the
  mismatch.

**The naming decision is no longer open.** Earlier notes left it between bare
subcommand lineages and runbook-stemmed ones. Phase 16 settles it as neither:
the contexts need a phase discriminator (`pre-image-status`,
`post-image-status`, …), which is the exception `artifact-runs.sh` names for
categories holding both phases side by side. That also requires a `--context`
option `run-time-machine.sh` does not have.
